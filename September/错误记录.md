## 一、环境与配置

### 1. `The api_key client option must be set`
- **原因**：没调 `load_dotenv()`，环境变量没读进来
- **解决**：文件开头加 `load_dotenv(r"...\.env")`
- **教训**：`import` 不等于执行，导入了 `load_dotenv` 但没调用它，等于没读

### 2. `api_key must be set`（读到了变量却还是报错）
- **原因**：`.env` 文件路径写错——文件在 `september/` 下，代码去项目根目录找
- **解决**：`load_dotenv()` 里写**绝对路径**
- **教训**：排查三查 → ①文件在不在 ②路径对不对 ③变量名一不一致

### 3. `api_key="OPENAI_API_KEY"` 不生效
- **原因**：传的是**字符串** `"OPENAI_API_KEY"`，不是变量的值
- **解决**：`os.getenv("OPENAI_API_KEY")`
- **教训**：字符串 ≠ 变量值

### 4. `AttributeError: module 'os' has no attribute 'get'`
- **原因**：函数名拼错
- **解决**：`os.getenv`（get + env）
- **教训**：读环境变量只有 `os.getenv`

## 二、Milvus

### 5. `uri ... is illegal`
- **原因**：uri 没带协议前缀
- **解决**：`http://127.0.0.1:19530`
- **教训**：uri 必须带 `http://` / `tcp://`，或以 `.db` 结尾走本地文件模式

### 6. `length(20480) should divide dim(1536)`
- **原因**：集合建成 1536 维，但 bge-m3 的稠密向量是 **1024** 维（20480 = 20 条 × 1024）
- **解决**：`dim=1024`
- **教训**：换 embedding 模型必须同步改 dim
  - bge-m3 = 1024 / bge-base-zh = 768 / text-embedding-3-small = 1536

### 7. Attu 里看不到数据（insert 成功了）
- **原因**：两个——①建集合时**没传 index_params**（没索引）②没 `load_collection`
- **解决**：建集合时传索引；插入后 `flush` + `load_collection`
- **教训**：完整链路是 **建索引 → load → 才能查/显示**，缺一不可

### 8. `create duplicate collection with different parameters`
- **原因**：同名集合已存在但 schema 不一致，Milvus 不允许覆盖重建
- **解决**：先 `drop_collection` 再建，或换个名字
- **教训**：建集合的代码**只保留一份**，别分散在多个脚本

### 9. 数据变成 80 条（预期 20 条）
- **原因**：`insert` 对相同主键是**追加**，脚本跑了 4 遍
- **解决**：改用 `upsert`（参数完全一样）
- **教训**：需要幂等写入时用 upsert

### 10. `search_data value ... is illegal`
- **原因**：把 `model.encode()` 返回的**整个字典**传给 `data=`
- **解决**：取 `result["dense_vecs"][0]`
- **教训**：**encode 返回字典，字典里才是向量**

### 11. `TypeError: unexpected keyword argument 'params'`
- **原因**：`AnnSearchRequest` 的参数名是 `param`（单数）
- **解决**：`param={"metric_type": "COSINE"}`
- **教训**：API 参数名必须完全一致

### 12. `fieldName(dense_vector) not found`
- **原因**：字段名写错，实际叫 `vector`
- **解决**：`anns_field="vector"`；稀疏是 `sparse_vector`
- **教训**：`client.describe_collection()` 看真实字段名

### 13. 稀疏检索报错 / 结果不对
- **原因**：稀疏向量传了 `COSINE`
- **解决**：稀疏**只能用 `IP`**（内积）
- **教训**：稠密 COSINE / L2，稀疏 IP / BM25

### 14. `RRFRanker() got unexpected keyword argument`
- **原因**：往 RRF 里塞了 `metric_type`、`params`
- **解决**：`RRFRanker(k=60)`，它**只有 k 一个参数**
- **教训**：RRF 只看排名不看分数，所以不需要度量类型

### 15. `nprobe` 参数无效
- **原因**：`nprobe` 是 IVF 系列索引的参数，你的索引是 HNSW
- **解决**：HNSW 用 `ef`；或干脆只写 `metric_type`
- **教训**：查询参数要和索引类型匹配

## 三、Python 基础 / 语法

### 16. `AttributeError: has no attribute 'create_nihao'`
- **原因**：方法名是自己编的，根本不存在
- **解决**：只能用真实存在的方法
- **教训**：不确定就 `dir(类名)` 查

### 17. `AttributeError: has no attribute 'create_scheam'`
- **原因**：拼错：scheam → **schema**（`s-c-h-e-m-a`）
- **解决**：用编辑器**自动补全**，别手打
- **教训**：Model Context Protocol 拼写靠补全，不靠记忆

### 18. `SyntaxError: perhaps you forgot a comma`
- **原因**：上一行末尾漏了逗号（比如 `command=r"python.exe"` 后面）
- **教训**：函数多个参数之间必须有逗号

### 19. `from json import tool` 报 ImportError
- **原因**：导错模块（`json` 里没有 `tool`）
- **解决**：`from langchain.tools import tool`
- **教训**：**自动导入会误加**！保存前扫一眼顶部新增的 import，不认识的删掉

### 20. 打印出 `<function xxx at 0x...>`
- **原因**：**忘了加括号**，拿到的是函数对象本身
- **解决**：`func()` 不是 `func`
- **教训**：这个坑我踩了三次（`print(danse_vector_search)`、`await session.list_tools`、`client.chat`）
  **方法必须加括号才执行**

### 21. `TypeError: 'method' object can't be awaited`
- **原因**：同上，`await session.list_tools` 少了括号
- **解决**：`await session.list_tools()`

### 22. 打印结果不对（打印了旧变量）
- **原因**：写了 `print(resp...)` 而不是 `print(response...)`
- **教训**：变量名要分清，`resp` 是第一次响应，`response` 是第二次

## 四、LangChain

### 23. `'ChatOpenAI' object has no attribute 'chat'`
- **原因**：把 LangChain 对象当原生 SDK 用（`llm.chat.completions.create`）
- **解决**：LangChain 用 `invoke()` / `bind_tools()`
- **教训**：**两套写法别混**
  - `ChatOpenAI` → `invoke()`
  - `OpenAI` → `chat.completions.create()`

### 24. `ValueError: Invalid input type HumanMessage`
- **原因**：`invoke()` 不接受单个消息对象
- **解决**：`invoke([human_message])` 用**列表**包起来
- **教训**：invoke 只认：字符串 / **消息列表** / PromptValue

### 25. `KeyError: 0`（流式输出时）
- **原因**：`stream()` 返回**字典**（按节点分组），不是列表
- **解决**：加 `stream_mode="messages"`，或遍历 `chunk.items()`
- **教训**：不确定返回类型就先 `print(type(...))`

### 26. `IndexError: list index out of range`（tool_calls[0]）
- **原因**：模型没决定调用工具，`tool_calls` 是空列表
- **原因2**：传给模型的是字符串 `"human_message"`（引号没去掉），模型看不懂
- **解决**：传变量不加引号；并加保护 `if not res.tool_calls:`
- **教训**：**变量名加了引号就变成字符串了**

## 五、MCP

### 27. `McpError: Connection closed`
- **原因**：服务端进程没起来（文件名对不上 → Python 找不到文件就退出）
- **解决**：`args` 里用**绝对路径**，且文件名要和实际一致
- **教训**：`Connection closed` 基本都是**服务端没起来**，单独跑一下 server 验证

### 28. `stdio_client() missing 1 required positional argument`
- **原因**：没传 `server_params`
- **解决**：`stdio_client(server_params)`

### 29. `ValueError: too many values to unpack (expected 2, got 3)`
- **原因**：版本差异——`streamable_http_client` 返回 **3 个**值
- **解决**：`as (read, write, _)`；注意 **stdio 是 2 个，http 是 3 个**
- **教训**：SDK 升级会改返回值个数

### 30. `call_tool` 报 `NameError` / 参数错误
- **原因**：①传了函数对象而不是字符串名 ②用了关键字参数而不是字典
- **解决**：`await session.call_tool("get_weather", {"city": "上海", "date": "2023-09-01"})`
- **教训**：**客户端和 server 是两个独立进程**，只能通过字符串名字调用

### 31. `isError=True`（工具调用失败）
- **原因**：参数名不匹配 / 工具未注册 / server 没保存
- **解决**：`print(result.content)` 看真实错误信息；用 `list_tools` 打印 `inputSchema` 核对参数名

## 六、规律总结（最重要）

### 高频错误模式 Top 5

| 排名 | 模式 | 典型报错 |
|---|---|---|
| 🥇 | **忘了加括号** | `method object can't be awaited`、打印出函数对象 |
| 🥈 | **名字/路径写错** | `has no attribute`、`Connection closed`、`not found` |
| 🥉 | **两套写法混用** | `'ChatOpenAI' has no attribute 'chat'` |
| 4 | **参数名/个数变了** | `unexpected keyword`、`too many values to unpack` |
| 5 | **配置没加载** | `api_key must be set` |

### 通用排查四步

1. **读报错最后一行**（真正的错误原因在最后）
2. **看报错类型**：`AttributeError`→名字问题 / `TypeError`→类型或参数 / `ValueError`→值不对 / `SyntaxError`→语法（逗号括号）
3. **打印中间结果**：`print(type(x))`、`print(dir(x))`、`print(x.model_dump_json(indent=2))`
4. **单独验证**：把有问题的部分单独跑一遍（比如单独跑 server）
